## 1. Executive Summary

- **Overall State:** Fractured hybrid state. The project is a split-brain repository combining a Windows desktop application (Python/PyWebView + React 19) and an Android port (`android/` NTFS junction pointing to `NovaDrop (OG)`).
- **Desktop State:** Functional backend modules, but clean production builds are completely broken out of the box due to a `.gitignore` rule omitting the PyInstaller spec file.
- **Android State:** Native unit tests pass (62/62), but 33 architectural and runtime defects (documented in `docs/DEFECTS.md`) remain unaddressed.
- **Can it be resumed cheaply?** The desktop application can be resumed cheaply (estimated 1–2 days to unblock builds, fix tool detection, and patch npm vulnerabilities). The Android application requires substantial stabilization before release (estimated 1–2 weeks).
- **Single Biggest Risk:** Engine rot and execution failure in production: desktop `media_downloader.py:480` falsely reports FFmpeg as missing due to an invalid CLI argument flag (`--version`), and `.gitignore:16` (`*.spec`) prevents clean desktop compilation.

## 4. What Is Broken

### Critical Severity

#### 1. Windows Desktop Executable Build Fails Cleanly
- **Reproduction:** Run `python build_windows.py` in project root.
- **Observed Behavior:**
  ```text
  ERROR: Spec file "C:\Users\Brandon\Downloads\Projects\Media Downloader\MediaDownloader.spec" not found!
  PyInstaller build failed with exit code 1
  ```
- **Root Cause:** `.gitignore:16` contains `*.spec`. `MediaDownloader.spec` was excluded from tracking on `main` and `phase4-engine-router`. (It was only committed once under an experimental untracked merge on `spike/engine-phase1b` at commit `8c27df8`).
- **Impact:** Project cannot be packaged or built into an executable or installer from this branch.
- **Evidence:** `audit-evidence/build_windows_run.txt`.
- **Confidence:** [Certain]

### High Severity

#### 2. FFmpeg Detection Logic Falsely Reports Missing Dependency
- **Reproduction:** Run `media_downloader.check_installed("ffmpeg")` in Python.
- **Observed Behavior:** Returns `False` even when `build_assets/tools/ffmpeg.exe` exists and is functional.
- **Root Cause:** `media_downloader.py:480` executes `[resolve_tool_path(tool), "--version"]`. FFmpeg rejects `--version` with `Unrecognized option '-version'. Error splitting the argument list: Option not found` and exits with error code, triggering `CalledProcessError` in Python.
- **Impact:** System assumes FFmpeg is absent, disabling audio transcode/muxing and embedded artwork extraction workflows.
- **Evidence:** `audit-evidence/backend_smoke_test.txt`.
- **Confidence:** [Certain]

#### 3. Default Extraction Routing Misclassifies Audio and Streaming Hosts
- **Reproduction:** Pass a SoundCloud, Bandcamp, or streaming media URL to `media_downloader.detect_tool()`.
- **Observed Behavior:** Returns `gallery-dl` instead of `yt-dlp`.
- **Root Cause:** `media_downloader.py:36-41` (`YTDLP_SITES`) only lists 13 explicit domains. Line 100 defaults all unmatched domains to `gallery-dl`. `gallery-dl` does not support audio platforms like SoundCloud, causing extraction failure.
- **Impact:** Downloads fail for major streaming and audio services.
- **Evidence:** `media_downloader.py:92-100`; `audit-evidence/backend_smoke_test.txt`.
- **Confidence:** [Certain]

#### 4. Frontend High-Severity Security Advisories
- **Reproduction:** Run `npm audit` in `frontend/`.
- **Observed Behavior:** 3 vulnerabilities reported (2 High, 1 Moderate).
  - `vite` 8.3.0 - 8.3.2 (High): Command injection / path traversal via `launch-editor` (GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw, GHSA-587h-7wmj-h5pm).
  - `source-map-js` 1.0.0 - 1.2.1 (High): Denial of service through indexed source-map section offsets (GHSA-68fv-2mgg-jv7q).
  - `postcss-selector-parser` <6.1.5 (Moderate): ReDoS in flat selector parsing (GHSA-rj75-hqrm-r3gf).
- **Root Cause:** Outdated dependency pins in `frontend/package.json`.
- **Impact:** Security exposure during development and bundle compilation.
- **Evidence:** `audit-evidence/npm_audit_summary.txt`.
- **Confidence:** [Certain]

#### 5. Android Room Database Destructive Migrations (DEF-004)
- **Reproduction:** Update schema version in `NovaDropDatabase.kt`.
- **Observed Behavior:** User download history and search records are completely wiped.
- **Root Cause:** `android/app/src/main/java/com/novadrop/android/data/local/NovaDropDatabase.kt:35` configures `fallbackToDestructiveMigration()` with `exportSchema = false`.
- **Impact:** Catastrophic data loss on schema updates.
- **Confidence:** [Certain] (DEF-004 in `docs/DEFECTS.md`).

#### 6. Android Scoped Storage Direct I/O Failure on API 29+ (DEF-025)
- **Reproduction:** Execute download job targeting external storage on Android 10+ device.
- **Observed Behavior:** `FileOutputStream` crashes with `FileNotFoundException` / `EACCES (Permission denied)`.
- **Root Cause:** `android/app/src/main/java/com/novadrop/android/engine/native/NativeExtractorEngine.kt:795` writes directly to public directory path without `MediaStore` insertion or SAF.
- **Impact:** All downloads fail on modern Android versions (API 29–35).
- **Confidence:** [Certain] (DEF-025 in `docs/DEFECTS.md`).

### Medium Severity

#### 7. Monolithic Architecture & Giant Files
- **Root Cause:** `app.py` is 2,995 lines containing the PyWebView host, local HTTP bridge, CORS handling, 62 IPC methods, background update checks, and OS window hooks. `media_downloader.py` is 1,716 lines combining CLI argument builders, psutil process trees, and thumbnail caching.
- **Impact:** Extreme maintenance friction, tight coupling, and high risk of regressions.
- **Confidence:** [Certain]

#### 8. Redundant Frontend In Codebase
- **Root Cause:** Root `index.html` (315 KB, ~5,000 lines) exists as a fallback legacy implementation alongside modern React 19 app in `frontend/`.
- **Impact:** Maintenance bifurcation; bug fixes in React are not mirrored in legacy HTML fallback.
- **Confidence:** [Certain]

#### 9. Frontend Lint Warnings Volume (1,393 warnings)
- **Root Cause:** `oxlint` reports 1,393 warnings across 26 JSX/JS files, including React state updates inside effects (`PlaylistInspectorModal.jsx:25`, `MediaThumbnail.jsx:74`), missing hook dependencies, and unescaped regex characters.
- **Impact:** Render cascading and subtle lifecycle bugs.
- **Evidence:** `audit-evidence/frontend_lint.txt`.
- **Confidence:** [Certain]

1. **Touch Target Sizing:**
   - *Desktop:* In `HeaderBar.jsx` and `NavigationRail.jsx`, several icon-only action triggers are bounded to `w-7 h-7` (28x28px), below accessible mouse/touch target recommendations (minimum 32–44px).
   - *Android:* Several action chips and inline icon buttons in `HomeScreen.kt` lack `minimumInteractiveComponentSize` padding, failing the Material 48dp touch target threshold.
2. **Layout Thrashing & Chunk Size:**
   - *Desktop:* `frontend/dist/assets/index-DLGbhH2Y.js` is 511.35 kB (exceeds Vite's 500 kB chunk threshold). Lack of route-level code splitting (`React.lazy()`) forces the entire player, inspector modal, and settings view into the initial bundle.
3. **Color Contrast & Theme Consistency:**
   - *Desktop:* Dark theme tokens in `tailwind.config.js` and `App.css` use high-contrast foreground text (`text-slate-100`) over deep tinted surfaces (`#090a0f`, `surface-2`). Secondary labels in `HomeView.jsx:81` (`text-[11px] text-slate-400`) have low contrast when layered over tinted category card gradients.
   - *Android:* Uses hardcoded color hex values throughout composables rather than relying strictly on `MaterialTheme.colorScheme` dynamic color tokens (`Theme.kt`).
4. **Window Insets & Edge-to-Edge (Android):**
   - In `MainActivity.kt`, Android 15 edge-to-edge window insets are incompletely wired; text inputs on `HomeScreen.kt` and `ExploreScreen.kt` do not adapt to `WindowInsets.ime`, causing keyboard occlusion when typing long URLs.
5. **Accessibility & Screen Reader Labels:**
   - In `DownloaderView.jsx`, card controls for pause, resume, and cancel render Lucide icons without explicit `aria-label` attributes on outer buttons, degrading screen reader accessibility.
6. **Visual Evidence:**

### Resolution Mechanics Under `sys.frozen`

- When frozen by PyInstaller, `sys.frozen` is set to `True`, and `sys.executable` points to `NovaDrop.exe` [Certain].

  This points to `dist/NovaDrop/` [Certain].
- **Candidate Search Order in `resolve_tool_path(tool)` (`media_downloader.py:246-280`):**
  1. `~/.media_downloader/tools/<tool>.exe` (user-updated directory in user home). Takes top priority so in-app engine updates bypass admin permission and take effect without rebuilding the application [Certain].

  4. `<exe_dir>/build_assets/tools/<tool>.exe`. Development staging directory fallback [Certain].

- **Handling of `sys._MEIPASS`:** `resolve_tool_path()` does **not** reference `sys._MEIPASS` [Certain]. This is by design: `MediaDownloader.spec` produces an `onedir` distribution (`exclude_binaries=True`, `COLLECT(...)`), not a `--onefile` bundle. In an `onedir` build, PyInstaller leaves all files uncompressed in the output folder beside `NovaDrop.exe`, rather than extracting them at runtime into a temporary `_MEIxxxx` directory [Certain].
- **`resolve_ffmpeg_dir()` (`media_downloader.py:283-319`):** Follows the same priority order (user tools -> `<exe_dir>/tools/` -> `_internal/tools/` -> `build_assets/tools/`) and returns `<exe_dir>/tools` when bundled.
